# Кабинет служб ЭлPay (Flutter Web)

Веб-кабинет для водоканала, электросети, садиков и других служб: абоненты из 1С,
начисления по месяцам, кто оплатил, реестр платежей обратно в 1С, напоминания
должникам. Плюс кабинет админа ЭлPay: службы пилота, подключение новой службы,
платежи без сопоставления, журнал действий.

**Демо:** https://ulankn8.github.io/elpay-demo/admin/ — открывать на компьютере.
Код входа всегда **4815**.

| Почта | Кто это |
|---|---|
| `jypar@oshvodokanal.kg` | сотрудник Ошводоканала |
| `nurgul@oshvodokanal.kg` | приглашённый сотрудник — первый вход |
| `a.kadyrov@elpay.kg` | админ ЭлPay |

Собран по концепту `concept/admin/` (18 экранов): цифры обзора совпадают с ним
до сома. Демо-реестр — 12 480 абонентов Ошводоканала, сентябрь 2026, срок оплаты
25 октября; часы кабинета идут от «14 октября 2026, 12:00».

**Заглушки:** вход (код из письма не отправляется), push и SMS (рассылка
записывается, но никуда не уходит), деньги (платежи — демо-данные). Обмен с 1С
по API — экран «скоро» с запиской, как он будет работать. Остальное работает
по-настоящему: файлы читаются и пишутся, данные сохраняются в браузере.

## Что можно попробовать

- **Импорт из 1С** — «Импорт из 1С» → «Скачать пример»: CSV в Windows-1251 с «;»,
  как его отдаёт 1С. Мастер сам узнаёт кодировку и разделитель, сопоставляет
  колонки по заголовкам 1С («Лиц_счет», «Абонент», «Кол_прож»…) и по содержимому,
  показывает ошибки до записи: дубль лицевого, потерянный ноль, улица с опечаткой,
  «3О1» вместо 301. Подсказки принимаются по одной или все сразу; подсказка,
  которая перепишет чужую карточку, не предлагается. Загрузку можно отменить
  в течение суток.
- **Начисления** — тот же мастер для Excel (.xlsx): 12 480 строк за месяц,
  новый месяц открывает период, недоплата прошлого становится долгом.
- **Абоненты** — фильтры по статусу оплаты, поиск по лицевому, ФИО, адресу и
  телефону, карточка с историей за полгода, корректировка начисления, ручное
  добавление с проверкой лицевого и улицы, выгрузка списка в Excel.
- **Платежи и реестр** — выгрузка в 1С: CSV в Windows-1251 или Excel, отметка
  выгруженного, повторная выгрузка пустая, автовыгрузка в 18:00.
- **Уведомления** — сегменты должников, push бесплатно подключённым в ЭлPay,
  SMS по желанию с ценой, не чаще раза в три дня одному абоненту, превью на телефоне.
- **Сотрудники** — приглашение только на рабочую почту службы, закрыть доступ.
- **Админ ЭлPay** — службы пилота, подключение новой службы по шагам,
  платежи без сопоставления с подсказкой лицевого (перестановка цифр, потерянный
  ноль, проверка по телефону и сумме), журнал действий.
- **Сброс демо** — «Сбросить демо-данные» внизу боковой панели возвращает цифры к началу.

## Запуск

```bash
cd app
flutter run -d chrome -t lib/admin/main_admin.dart
```

Публикация на витрину (кладёт сборку в `../admin/`, движок CanvasKit — рядом,
без CDN):

```bash
FLUTTER=/opt/flutter/bin/flutter tools/build_admin.sh   # из корня репозитория
```

Для проверки Playwright-ом собирать с деревом доступности, иначе текст во
Flutter-канвасе не виден:

```bash
flutter build web -t lib/admin/main_admin.dart --no-web-resources-cdn \
  --dart-define=ENABLE_SEMANTICS=true -o build/web_admin
```

## Как устроено

```
lib/admin/
  data/       чистый Dart: модели, кодировки, CSV, XLSX, движок импорта,
              адреса Оша, реестр в 1С, демо-реестр (seed), AdminStore
  state/      Riverpod: AdminStore в контейнере, ревизия, мастер импорта
  platform/   выбор файла, скачивание, drag-and-drop (web) и заглушка (VM)
  ui/         тема и компоненты кабинета (kit.dart), оболочка, экраны
  main_admin.dart
```

- **Общий с мобильным приложением только `lib/core`** (LocalStore, Clock,
  Result, format, tokens). Мобильное приложение не импортирует ни одного файла
  кабинета. Оба правила проверяет `test/architecture_test.dart`, как и то, что
  `admin/data` не знает ни про Flutter, ни про Riverpod, ни про браузер.
- **Демо-реестр не хранится, а генерируется** (`data/seed.dart`) из
  детерминированного генератора: 12 480 абонентов, платежи, долги. В браузере
  лежат только правки пользователя (ключи `adm.*` в localStorage с префиксом
  `elpay_admin.`) — иначе не уложиться в 5 МБ и не пересобрать демо без
  миграций. `String.hashCode` на вебе и на VM разный, поэтому свой `stableHash`.
- **Ревизия вместо identity.** Riverpod 3 не уведомляет, если провайдер вернул
  тот же объект. Каждое действие идёт через `AdminActions.run`, оно поднимает
  `revisionProvider`; экраны читают хранилище через `ref.admin`, который на
  ревизию подписан. Тяжёлые сводки (обзор, периоды, выгрузки) кэшируются
  по номеру ревизии.
- **Файлы** — через `FileGateway`; в виджет-тестах его подменяют, поэтому
  импорт проверяется целиком через интерфейс без браузера.

## Проверка

```bash
flutter analyze
flutter test test/admin test/architecture_test.dart
```

- `file_formats_test` — Windows-1251, UTF-8 с меткой, UTF-16, разделители, xlsx;
- `import_engine_test` — сопоставление колонок и все виды ошибок импорта;
- `seed_test`, `admin_store_test` — цифры концепта, импорт, откат, реестр, рассылки, сброс;
- `admin_ui_test` — вход, роли, импорт через интерфейс;
- `admin_screens_test` — каждый экран на 1440 и 1100 px без переполнений.
  В релизной веб-сборке Flutter не рисует полосы переполнения, поэтому их
  ловит только этот тест.
