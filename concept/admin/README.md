# Кабинет служб ЭлPay — концепт

Статичный визуальный концепт веб-кабинета для водоканала, электросети, садиков
и других служб. 18 экранов и страница-записка про API в одном файле `index.html`
(открыть в браузере). Скриншоты каждого экрана — в `shots/`.

Решения заказчика, на которых построен концепт:

- **Абоненты добавляются тремя способами**: выгрузкой из 1С (универсальный мастер
  CSV и Excel с сопоставлением колонок), вручную и — следующим этапом — по API.
  API оформлен отдельной запиской «для размышления» (экран 19).
- **Роли**: у каждой службы свой кабинет, она видит только своих абонентов и
  платежи; ролей внутри службы нет — все сотрудники с одинаковыми правами.
  Админ ЭлPay заводит службы, выдаёт доступ и разбирает спорные платежи.
- **Функции службы**: статус оплаты по каждому абоненту, ежемесячная загрузка
  начислений, выгрузка реестра платежей обратно в 1С, уведомления должникам.

Экраны:

| № | Экран |
|---|---|
| 01–05 | Вход, обзор, абоненты, карточка абонента, ручное добавление |
| 06–10 | Импорт из 1С: файл → колонки → проверка до записи → итог и журнал; начисления по месяцам |
| 11–13 | Платежи, выгрузка реестра в 1С, уведомления должникам |
| 14–15 | Сотрудники и доступ, интеграция по API (экран «скоро») |
| 16–18 | Админ ЭлPay: службы пилота, подключение новой службы, платежи без сопоставления |
| 19 | Записка: интеграция с 1С по API — нужна ли она на пилоте |

Все цифры вымышленные и сходятся между экранами — источник в `DATA.md`.
Жительница Токтогулова Айгерим та же, что в мобильном приложении: её вода
205 сом за сентябрь не оплачена, срок 25 октября.

Как собрать: `python3 build.py` (экраны — `screens/NN-имя.html`, первая строка —
метаданные; заготовки `{{side:…}}`, `{{top:…}}`, `{{i:…}}` описаны в `build.py`).

После утверждения переносится в код.
